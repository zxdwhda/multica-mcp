# OAuth 迁移检查

## 已核实的问题（2026-10-02，Asia/Shanghai）

公网 MCP 和授权端点已由新加坡轻量服务器上的 Multica MCP 容器提供，运行版本为 0.4.0 / d524ae3。此次 `invalid_client` 并非请求仍指向 FC。

ChatGPT 重连沿用迁移前的 DCR client ID；原客户端注册存在于旧 OAuth 存储，当前服务器的存储中没有这条记录。服务器在读取注册记录失败时返回 `invalid_client`，因此还没有进入 PAT 验证阶段。只创建新客户端的协议 smoke 能通过，但没有覆盖已有插件连接的迁移兼容性。

## 修复边界

1. 从当前服务器配置核实 OAuth origin、目标存储和加密 seed；从原客户端记录核实唯一的 ChatGPT 回调。诊断中不输出凭据或完整授权 URL。
2. 只迁移该客户端注册元数据：用原 seed 解密，以当前 seed 重新加密。目标必须确认为缺失，使用禁止覆盖写入，再读回比较。客户端 ID 和回调不变。
3. 不迁移旧账号 grant、access token 或 refresh token。使用当前自建 Multica 身份在原插件中正常重连。
4. 检查原插件账户不再显示“需要更新身份验证”，然后在普通 ChatGPT 对话实际调用只读工具。进程健康、注册成功或授权页可打开，都不能替代此验收。

此次单条注册修复已完成读回校验，并通过原账户 OAuth 重连。没有重启容器、重新发布 FC 或修改客户端权限。旧存储保留。

重连后，普通 ChatGPT 对话按已加载的任务 Skill 实际读取 WILD-1，返回 HTTP 200；标题为“安装验收：Mac Codex 只读执行”，状态 done，与本地 CLI 读取一致。原 MCP 连接独立读取同一任务也返回 HTTP 200。此次未创建或更新任务、发评论或派发 Agent。

## 后续迁移验收

- 新客户端：DCR 注册、PKCE、授权码兑换、刷新和撤销。
- 已有客户端：原连接触发重连，核对客户端注册在当前 seed 下可读取，然后完成回调和真实 MCP 调用。
- 存储读取异常：当前实现把注册缺失、解密失败等读取错误统一返回 `invalid_client`；应核对服务端存储错误，不能仅凭这个响应判定客户端 ID 无效。

部署 PAT 是当前加密 seed 的输入。变更 PAT 或存储时须同时处理客户端注册兼容性；单纯让用户重复点击重连不会重新注册已缓存的客户端。
