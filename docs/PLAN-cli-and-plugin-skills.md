# Multica 本地 CLI 与网页插件 Skills 计划

日期：2026-10-01（Asia/Shanghai）。用户已授权完成本地 CLI + Skill 和现有网页 MCP 插件 Skill 适配。

## 目标与范围

本机日常协作优先使用已有 Multica CLI 与官方 multica-cli Skill；ChatGPT 网页保留当前 Multica MCP 连接、身份、完整 API 能力与插件受众，补齐远程工具适配的业务 Skills。参照飞书的技能入口、按需参考、参数合同及失败恢复方式。

独立仓：zxdwhda/multica-mcp。隔离工作区：projects/.worktrees/multica-cli-skills；分支 codex/multica-cli-skills。根仓及其他仓既有修改不属于本任务。

## 执行顺序

1. 核对官方 Skill 固定来源、现有 CLI 版本与身份；安装到本机共享 Skills 发现目录，保留来源与许可，不升级 CLI 或改变账号。
2. 在现有 multica-mcp 仓维护网页 Skill 源码与构建产物。覆盖 shared、任务与评论、项目、Agent 与运行、Skills/小队/自动任务等；官方业务规则保留并转换为实际 MCP 参数，不把本机命令或登录凭据带到远端。
3. 保留全部已注册工具，网页 Skill 使用已有原始 API 做评论摘要、线程筛选与有界返回；服务端可选读取开关和游标透传作为独立扩展准备。统一分页、部分失败、触发执行与已有授权语义。
4. 添加插件包，复用原 MCP SDK、OAuth 及已有连接。先查明网页插件真实身份和更新方式，再更新同一插件；不新建替代插件。网页 Skill 由插件包提供，服务端标准资源作为可选增强。MCP 统一使用轻量服务器，FC 不再部署。
5. 按改动运行 Go 测试、竞态检查、vet、构建，校验全部 Skill 链接、manifest、来源记录与无凭据打包。经代码审查修复实际问题。
6. 完成必要部署、插件更新与安装，进行 CLI 和远程只读真实调用，以及普通 ChatGPT 对话的 Skill 加载和工具调用验收。发布/协议/宿主/业务层级分别记录；未验证项不写成完成。

## 验收条件

- 本地官方 Skill 可被宿主发现，已有 CLI 在指定工作区真实只读成功。
- 网页 Skills 按实际 MCP schema 执行；无运行本机 CLI 或读取本机凭据指令。
- 原 395 个工具的名称、调用合同和完整能力兼容；新增工具和协议扩展有行为验证。
- 原插件身份、连接、受众和既有配置保留，网页普通对话可加载 Skill 并成功执行只读任务。
- 不创建真实业务任务、不发消息、不派发 Agent；测试不触发后台执行。
