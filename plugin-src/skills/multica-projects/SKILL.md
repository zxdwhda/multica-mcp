# Multica 项目与飞书协作

先读 [执行约定](references/execution.md)。项目查询优先 `multica_list_projects` 和 `multica_get_project`，工作区、成员、仓库关联、归档和其他项目设置用 `multica_api_catalog` 发现实际工具。

先核对当前工作区和真实项目 ID，再查询项目任务；按实际分页继续。报告分清已完成、进行中、阻塞、暂停与尚未启动，不把历史卡和暂停项自动归入当前 Backlog。需要变更项目时依据用户明确范围执行并读取复核；不要因名称接近就合并项目或切换工作区。

## 配合飞书工作台

两个插件保留各自连接与身份，按内容职责配合：

| 信息 | 查询来源 |
|---|---|
| 执行任务、负责人、状态、评论、Agent 运行 | Multica |
| 会议、日历、会议纪要、文档与知识库 | 飞书工作台相应 Skill |
| PR、CI、合并、发布 | 所属代码平台与实际部署记录 |

用户要求“根据会议安排任务”时：读取指定会议/纪要，提取行动项和依据链接，确认真实 Multica 项目和负责人，按已有授权创建任务并回读。用户只要求总结或建议时生成报告，不写入任务。

用户要求“汇总进展到飞书”时：读取 Multica 项目任务和相关讨论；使用飞书文档/Markdown Skill 写入指定文档，保留任务链接和更新时间，再回读核对。发聊天消息需要用户明确指示；更新文档不自动授权群发。

不默认双向同步、复制飞书身份到 Multica 或批量迁移。跨系统引用优先链接；汇总中明确资料缺失与来源日期。飞书插件不可用时先完成 Multica 查询，说明飞书部分尚未验证。
